# DiskScope

Native macOS (SwiftUI, macOS 14+) disk-usage browser, like ncdu, with a Finder-style UI. SwiftPM package; no Xcode project (only Command Line Tools are installed).

## Build / run
- `./build-app.sh` → `build/DiskScope.app` (universal arm64+x86_64, Hardened Runtime, ad-hoc signed).
  `--install` copies to /Applications, `--dmg` makes a DMG. `SIGN_IDENTITY=` / `NOTARY_PROFILE=` for Developer ID + notarization.
- Per-arch builds use `.build/arm64` and `.build/x86_64` scratch paths (XCBuild isn't available, so `--arch a --arch b` fails; script uses `--triple` + `lipo`).
- A folder path argument starts a scan on launch: `open build/DiskScope.app --args ~/dir`.
- `swift scripts/make-icon.swift` regenerates `Resources/AppIcon.icns`.
- Tests: `Tests/run-tests.sh` (swift-testing, ~3 s, prints coverage; `--filter X` for a subset; `SCRATCH=.build/x` to use a separate build folder so parallel builds don't collide). Works with plain Command Line Tools (script adds the Testing.framework search path + `-disable-cross-import-overlays`) and unchanged with full Xcode (CI). Model tests must inject a fake `AppModel(trasher:)` — never touch the real Trash.

## CI / releases (.github)
- `workflows/ci.yml` — every push to main + PRs: `Tests/run-tests.sh`, `./build-app.sh`, uploads the zipped app (14 days).
- `workflows/release.yml` — tag `vX.Y.Z`: tests, `./build-app.sh --dmg` (VERSION from the tag, BUILD_NUMBER = run number), publishes a GitHub release with the DMG + `.sha256`. "What's new" comes from `release-notes/<version>.md`. Optional Developer ID signing + notarization when secrets `MACOS_CERTIFICATE_P12` (base64), `MACOS_CERTIFICATE_PASSWORD`, `MACOS_SIGN_IDENTITY`, `NOTARY_APPLE_ID`, `NOTARY_TEAM_ID`, `NOTARY_PASSWORD` are set; otherwise ad-hoc, and the notes explain "Open Anyway".

## Layout (Sources/DiskScope)
- `Scanner.swift` — parallel walker (worker threads, readdir + fstatat relative to dir fd, never follows symlinks; each opened subdir is checked against the (dev, ino) seen when listed; non-UTF-8 names flagged, not traversed). Disk size = st_blocks*512; hard links counted once. Skips `Scanner.skipPaths` below the root (`/System/Volumes/Data`, `/Volumes`, `/dev`, Software Update's `mnt1` mounts). `scan(...)` throws on unreadable root, returns nil on cancel.
- `FileNode.swift` — tree node; dirs hold aggregated totals. **`parent` is `unowned`**: never retain a node whose ancestors may be freed. Anything that drops a subtree must first call `AppModel.purgeReferences(into:)`; views that keep nodes across tree changes (e.g. sunburst segments) hold them weakly.
- `AppModel.swift` — @MainActor state: scan/rescan (subtree splice), back/forward history, cached sorting (`sortedChildren`), search, Trash (`TrashGuard`: blocks system paths and unreliable items; before moving re-verifies realpath of parent, kind, and file size/mtime). Scan roots are canonicalized with realpath. `LaunchSafety` stops double-click from launching apps/scripts. View modes: list, columns, sunburst.
- `HiddenSpace.swift` — "Not in scan" for whole-disk scans: getfsstat + getattrlist(`ATTR_VOL_SPACEUSED`) for other APFS volumes in the same container, `tmutil listlocalsnapshots` for the snapshot count. `compute(...)` is the pure, testable part; `isCovered` must mirror Scanner's skip rules.
- `Sunburst.swift` — sunburst view (⌘4): layout + hit testing + legend; includes a "Not in scan" slice at the root of a whole-disk scan.
- Find Duplicates: `DuplicateFinder.swift` (engine: walk, group by size → SHA-256 of the first 64 KB → full SHA-256; hard links collapsed), `DuplicatesModel.swift` (window state, Keep/Remove marks and keep rules — every set keeps ≥ 1 copy), `DuplicatesView.swift` (window UI), `ContentPreview.swift` (text / image / AV / PDF / Quick Look previews). **Find Duplicates never deletes or trashes anything itself**: "Removal Script…" writes a bash script the user reviews and runs (`bash remove-duplicates.sh` = dry run, `--apply` = move to Trash after re-checking `shasum -a 256` of the file and its kept copy, skipping anything that changed); saved non-executable. CSV export (scan and duplicate sets) must neutralise formula-like fields. **Rule:** duplicate and preview code must only open regular files — `O_NOFOLLOW | O_NONBLOCK`, then `fstat` for `S_IFREG` and the expected (dev, ino) — and must skip dataless placeholders (`st_flags & SF_DATALESS`), since reading those blocks (FIFOs) or downloads from the cloud.
- CSV: `CSV.swift` (shared RFC 4180 writer with formula neutralising), `ScanExport.swift` (File › Export as CSV: folder items or entire scan; streamed in chunks on the main actor, never caches sorted copies of every folder), duplicate sets via `DuplicatesCSV` in the duplicates code.
- Ask Claude files: `ClaudeClient.swift` (raw HTTPS + SSE; Swift has no official SDK), `KeychainStore.swift`, `DiskSummary.swift` (what gets sent), `AskClaude.swift` / `AskClaudeView.swift` (panel + Settings tab).
- Ask Claude (optional panel, off by default) — the **only** networking in the app: sends a text summary of the scan (names relative to the scan root, home shown as `~`, sizes, dates, "Not in scan") to Anthropic's API over HTTPS with the user's own API key (Keychain, entered in Settings). Never file contents; Claude gets no tools that open/move/delete. Keep "What gets sent" showing exactly the payload, and keep the README/site privacy wording in sync if this changes.
- `Volumes.swift` — mounted volumes + `VolumeStore` (refreshes on mount/unmount).
- UI: `ContentView.swift` (split view, toolbar, welcome, scanning), `Sidebar.swift` (Locations/Favorites), `ColumnBrowser.swift` (Finder column view), `ListBrowser.swift` (table + search results), `Components.swift` (icons, bars, path/status bars, preview).
